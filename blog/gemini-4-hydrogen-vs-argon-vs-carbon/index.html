Gemini 4 Hydrogen vs Argon vs Carbon: Which Model for Which Job — and How to Run All Three in One Session

By Bronze · November 14, 2026 · 7 min read

Google now has three Gemini 4 models, and the expensive mistake is picking the strongest one for everything.

Hydrogen arrived on November 12, joining Carbon and Argon. They are not three rungs on one ladder. They are three different jobs: one thinks deep, one does most of the work, one executes fast and cheap. Used wrong, you pay frontier prices for typing speed. Used right, the cheap model does most of the work and the expensive one only shows up where it earns its keep.

Here is how they actually differ — and the workflow that lets you use all three in a single session without thinking about switching.

The three models, in one paragraph each

Carbon is the deep thinker. Google calls it the frontier model for deep, long-horizon reasoning on your hardest problems. It leads the family on the Artificial Analysis Intelligence Index at 59, against 50 for Argon. You reach for it when the problem is the thinking itself: system architecture, a subtle bug that has survived three fixes, a security review. It went generally available on November 10, 2026.

Argon is the workhorse. Also a frontier model, also built for deep reasoning — but Google's own guidance is that Argon "remains the ideal choice for the majority of software engineering and knowledge work." Translation: Carbon is stronger, but it spends more tokens per turn exploring, reasoning, and verifying. For the ordinary run of coding and knowledge work, Argon gets you nearly the same answer for fewer tokens. It went generally available on October 13, 2026.

Hydrogen is the execution engine. Launched November 12, built for rapid execution across agentic workflows: writing code, running tests, verifying changes, doing it again. It even beats Argon on the Artificial Analysis Intelligence Index at its default high thinking level — 51 against 50, reaching 54 at its highest xhigh setting. Against the previous generation, Gemini 3.8 Flash, it finishes tasks 2.5 times faster and more than triples Terminal-Bench 4.1 scores, from 18.2% to 57%, while cutting fabricated claims by more than 5x. It has four thinking levels — low, medium, high (default), and xhigh — so you pay for only as much reasoning as the task needs.

The pricing needs a warning label. Carbon and Argon share the same per-token price, but that does not mean the same bill: Carbon consumes more tokens for the same job, because it thinks longer. And both prices double on December 1, 2026 — the $2/$10 rate is an introductory price. Hydrogen's $1.50/$7.50 is flat across its entire context window, with no scheduled jump announced.

Do the math on a concrete workload — 1 million input tokens and 200,000 output tokens. Hydrogen costs $3.00. Carbon or Argon costs $4.00 today and $8.00 from December 1. The gap is small on one task and enormous across a month of agent runs.

The mechanism that makes three models practical: Orchestrator

Knowing which model fits which job is only half the problem. The other half is switching — and nobody wants to stop mid-task, copy context into a new chat, and pick a different model by hand.

That is what Orchestrator in Google Antigravity does. Instead of one model from start to finish, it dynamically switches between models like Carbon and Hydrogen inside the same session. Google's numbers, on Terminal-Bench 4.0: Orchestrator reaches near-Carbon task success rates while consuming 24% less quota and finishing 19% faster on average.

The pattern Google describes is a small team, not a single worker. Carbon acts as coordinator; Hydrogen powers worker and verifier agents that build and test changes simultaneously across isolated workspaces. The expensive brain plans and checks; the cheap hands type and run.

How to run it: one session, three roles

Here is the workflow the mechanism implies, applied to a real job — say, adding authentication to an existing app:

1. Give Carbon the design. Open the session and hand the coordinator the hard part: the auth architecture, the threat model, what "done" looks like. This is the one decision where deep reasoning pays for itself. Ask for a plan with named files, named functions, and the tests that will prove each piece works.

2. Let Hydrogen execute. The implementation — writing the code, wiring the routes, running the tests — goes to Hydrogen workers. This is where the volume lives, and Hydrogen is built for exactly this: surgical edits, batched file reads, fast iteration. If a tool call fails or a search comes back empty, Hydrogen adapts instead of stalling, which is the failure mode that used to kill cheap-model runs.

3. Let Hydrogen verify in parallel. A second Hydrogen agent checks the work while the first one is still building: run the tests, read the diff, look for the places where the code contradicts the plan. Verification is a fast, repeatable job — it does not need the frontier model.

4. Bring Carbon back for the final review. One pass over the finished diff, by the model that designed it. Did the implementation drift from the plan? Is there a security hole the verifier missed? Carbon's job is to catch the one thing that matters, not to re-read every line.

5. Keep the cheap model on the small stuff. Between the big jobs, Hydrogen handles the everyday work directly: drafting, research, summarizing dense files. It is also the model now running inside Google Search for all users globally, and inside the Gemini app — the same speed that makes it cheap makes it the default for anything interactive.

Two habits make this work in practice. First, write the acceptance criteria before you start — "the login route returns 401 without a token, 200 with one" — because a verifier can only check what you stated. Second, watch token counts per task, not per-token prices: Carbon's bill is higher than its price tag suggests, and the only way to know by how much is to measure your own workloads.

The rule of thumb

  • Architecture, a hard bug, a security decision → Carbon.
  • The coding and knowledge work you do every day → Argon.
  • Writing, testing, verifying, and anything you run in bulk or in parallel → Hydrogen.
  • A job with all three phases → Orchestrator in Antigravity, and let it switch for you.

The point is not that Hydrogen replaces Carbon. It is that most of a software task is not deep thinking — it is execution. Pay frontier prices only for the thinking, and let the fast model do the typing.
