Edge-TTS vs Kokoro: Two Free Ways to Make a Voice — Which One Belongs in Your Videos?

By Bronze · November 11, 2026 · 5 min read

This morning my own voice tool froze on me.

I clicked "Generate Voice," picked a Microsoft Edge voice, waited. And waited. No audio. No error. No timeout message. Just a button that looked busy and an output folder that stayed empty.

That freeze is exactly why I built the tool with two engines instead of one — and why the choice between Edge-TTS and Kokoro is not really about which one sounds better. It's about which one you can trust when you're shipping videos on a schedule, and which one you can trust when those videos start making money.

Why I needed both

I make faceless videos. No camera, no real voice on the mic. For months the workflow was backwards: render the video first, then squeeze a voiceover into shots already cut. The voice always lost — a line would spill into the next shot, or I'd speed up the narration until it sounded rushed.

So I flipped it: script first, voice second, render last. The voice decides how long each shot lives. I built a small desktop tool for this — Voice Studio — that takes a script one line per shot, generates each line separately, stitches them with controlled pauses, and exports two files: voice.mp3 and timings.json, a map of exactly when each line starts and ends. Picture and voice line up by construction, not by hope.

The tool needed voices. Free ones, because the budget here is zero. That search narrowed to two real options.

Edge-TTS: the best free voices, on someone else's terms

Edge-TTS uses the same neural voices as Microsoft Edge's Read Aloud feature. The quality is genuinely high — these are not robotic formant voices from 2010. It needs no API key, costs nothing, and for my use case it had one killer feature: Vietnamese.

For Vietnamese there are exactly two voices: NamMinh, a male voice, and HoaiMy, a female voice. That's it. Two. But two is infinitely more than zero, which is what every open model I tried offered. My desk robot speaks Vietnamese through NamMinh, and my Vietnamese voiceovers come from the same place.

The catch is how Edge-TTS works. It is not an official, documented API. It's a community-maintained route into an endpoint Microsoft runs for its browser. That means:

  • It can hang. Like it did this morning — the stream sometimes comes back empty, or stalls for 30 seconds or more, and if your code doesn't set a timeout and retry, your app just sits there forever. Version 1 of my tool made exactly that mistake.
  • Microsoft can throttle your IP or change how the endpoint authenticates, at any time, without notice. There is no support ticket to file. It works until it doesn't.
  • The licensing is a grey area. The terms don't clearly grant commercial rights to the output. In Microsoft's own Q&A forums, the guidance for commercial use points you to Azure Speech — the paid product. I am not a lawyer, but "the vendor's own staff suggest paying if you want to sell things with this" is a signal I take seriously.

Kokoro: less glamorous, completely yours

Kokoro-82M is a small open text-to-speech model released under Apache 2.0. That license matters more than any feature: commercial use is explicitly fine. You can monetize videos with it, sell audio made with it, ship it inside a product. No grey area.

It runs fully offline on your own machine. The build I'm using is the sherpa-onnx package, kokoro-en-v0_19, which bundles 11 English voices in a single model file — American and British, male and female. The voice of my English channel is one of them, am_adam.

No network means no hangs, no throttling, no surprise shutdowns. When I tested the pipeline with a four-line script, the tool produced 8.380 seconds of audio, and the timings file matched the actual file length measured by ffprobe to 0.0000 seconds. Boring, predictable — exactly what a production tool should be.

The limitations are real. The voice selection is fixed — 11 voices, not hundreds. The delivery is good but flatter than Microsoft's best; you earn back some life with shorter lines, faster pacing (I run it at 1.25x), and deliberate pauses. And there is no Vietnamese voice at all, so for my Vietnamese content Kokoro isn't an option today.

What I actually do now

English narration for videos I intend to monetize goes through Kokoro. Not because it sounds the best — it doesn't — but because it's the voice I fully own the rights to use, and it will still be working the morning Microsoft decides to lock a door. When money is attached, "probably fine" is not a license strategy.

Vietnamese narration still goes through Edge-TTS, because right now it's the only free option that exists. I accept the two risks with my eyes open, and I engineer around the one I can control: every Edge call in the tool needs a timeout, a retry, and a visible error instead of a silent freeze — the fix going into the next version after this morning's lesson. The risk I can't control, the licensing grey area, is exactly why Vietnamese content is not where I'd build a revenue line today.

If you're picking one: pick based on what breaks your project. If a dead API on upload day breaks you, go offline and open. If your language isn't in the open models yet, use the free cloud voice — but wrap it in timeouts, keep a fallback ready, and don't build your income on rights you were never actually granted.

Free is a price. It just isn't always the whole cost.
